# 独立レビュー手順
1. GAME-DEVELOPMENT-STANDARD.md を読み、担当・対象commit・現在の制作/LOCKを確認。
2. 制作担当の作業ツリーを動かさず、隔離したコピーで基準commitと対象commitを比較。コードレビューと通常テストの結果を分ける。
3. 必要な既存依存だけ使用。インストールやネットワーク変更が必要ならその工程を止める。検証用サーバーは127.0.0.1に限定し、既存ポートを奪わない。
4. 起動した実体とcommitの対応を確認。localhost/公開URLだけで最新版と決めない。公開版を新headの検証に代用しない。
5. PCの既存Chrome等で通常入力を通す。ユーザーの途中セーブ・記録・開いているタブを保護する。専用の隔離状態が用意できないときは続きの破壊につながる操作をしない。
6. 画面寸法・開始/選択/戦闘/結果のスクリーンショット、入力、console/pageerror、終了コードを保存。debug直行と自動モードは別結果。
7. 機械判定の対象範囲を確かめる。check.js の終了コード0だけで合格にしない。各異常数と要求周回完了も判定する。
8. 重要度と再現条件を制作担当へ受渡す。受信確認がなければ受渡しは未完。修正commitで別担当が同じ条件を再試験する。
9. 作成した一時サーバーと検証タブだけを閉じ、既存作業へ戻す。公開・merge等は適用される既承認範囲と安全条件を別工程で確認する。既承認内の操作に毎回の本人再確認を必須化せず、現在の禁止を優先する。本ケースのPRはdraft更新まででmerge/deployは禁止。
